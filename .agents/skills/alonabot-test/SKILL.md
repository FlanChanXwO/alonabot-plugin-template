# 验证插件的变更

本技能负责选择检查方式、决定测试是否提交，以及如何如实报告结果。提交规则以[编码规范「测试提交规则」](../../../docs/coding-standards.zh-CN.md#测试提交规则)及其[本仓差异](../../../docs/coding-standards.zh-CN.md#本仓差异)为准，命令见[开发指南](../../../docs/development.zh-CN.md#验证改动)。

## 从实际风险选择检查

先读 diff、负责的代码和已有测试，想清楚哪个输入、结果或失败路径还没被证明。修 Bug 时尽量先复现出行为上的失败；工具缺失或编译失败不算复现。

- 文档和普通注释只检查内容、链接和格式，不为凑数运行产品测试。
- Go、依赖或 CI 改动按开发指南运行 gofmt、`go build ./...`、`go vet ./...`、`go test -race ./...` 与五平台 pure-Go 构建；组件资源或 `plugin.yaml` 改动另运行 `alonabot check .`。
- 测试通过后，没有新的改动、失败或未解决的问题，就不再重跑或扩大范围。

## 哪些测试提交

- **提交**：覆盖真实入口的集成测试。本仓 `plugin_test.go` 使用 `plugintest` 通过公开 `New()` 驱动真实 Core 与测试 Adapter，覆盖 `/hello` 和配置。
- **数量**：一个 PR 默认只提交一个覆盖主路径的集成测试；多列时在 PR 正文写明理由。
- **不提交**：单元测试、边界穷举、回归复现、临时测试和 SDK 边界检查，写在包目录下的 `*_local_test.go` 中（已被 `.gitignore` 忽略）。不属于任何 Go 包的一次性脚本放在 `tmp/test/`。
- 同类情况合并成表驱动测试；不为 getter、构造函数或显而易见的分支写测试，不为测试导出私有符号。

## 如实报告

- 普通测试不访问真实平台，也不使用用户的 data_dir；模拟端、交叉编译和真实平台的结果分开写。
- 失败时保留完整错误，先找第一个原因；确定性的失败没有改动就不反复重跑。
- PR 或回复中列出实际运行的命令、平台和结果，包括本地跑过但没有提交的测试，并写明提交的测试新增了多少行。
